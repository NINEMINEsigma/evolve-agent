# Plan Command

将用户消息中 `$plan` 之后的内容视为本次任务输入。

1. 每次响应以 `[MODE: PLAN]` 开头。
2. 先读取并遵循 `riper-core` 与 `plan-mode` skills。
3. 根据任务输入定位 `.tasks/` 中的对应任务文件；存在时先读取其研究结论、任务进度和既有修订记录。
4. 补充阅读制定计划所需的源码，形成包含精确文件路径、组件关系、函数或类签名、数据结构、错误处理、依赖变化和测试方法的技术规范。
5. 将实施工作转换为编号、顺序明确、可独立审查的原子操作清单。不得编写实现代码。
6. 若任务文件已存在，将计划写入该文件；对既有计划的修正必须追加记录，不得覆盖原内容。
7. 计划完成后读取并执行 `review-plan` skills 审查标准。优先使用可用的多代理工具委派独立审查；无法委派时直接完成同等审查，并汇报审查结论。

不得自行转入 EXECUTE 模式。
