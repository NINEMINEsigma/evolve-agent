# Plan Review Command

将用户消息中 `$review-plan` 之后的内容视为待审查任务文件路径。未提供路径时，询问用户要审查哪个文件；一次只审查一个任务文件。

1. 以 `[MODE: PLAN-REVIEW]` 开头。
2. 读取 `riper-core`、`plan-mode` 与指定任务文件。
3. 只读审查，不修改任务文件、不编写代码、不切换 RIPER-5 模式。
4. 对每个判定引用任务文件中的具体内容，不臆测代码实现。

按以下维度分别给出“通过 / 警告 / 缺陷”：

- 必需规划元素：文件路径、组件关系、函数或类签名、数据结构、错误处理、依赖管理、测试方法。
- 实施清单质量：编号与顺序、原子性、依赖关系、遗漏、跳步或缩略。
- PLAN 模式合规性：是否混入实现代码、示例代码或模糊占位描述。
- 架构合理性：职责边界、复杂度扩散、参数或数据流问题、与原始任务的对齐程度。
- 可执行性：是否足以直接进入 EXECUTE 模式，是否存在悬空文件、函数或符号引用。

最后输出总判定：“可执行 / 需修订后执行 / 需重新规划”，并分别列出阻塞性缺陷与建议修订项。
