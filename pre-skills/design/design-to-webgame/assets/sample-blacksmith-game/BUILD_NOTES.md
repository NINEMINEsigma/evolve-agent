# 样例构建笔记：《铁匠恋歌：真心之锤》

本样例是从一份完整的游戏设计文档（`设计文档原文.txt`，锻造经营+恋爱养成+剧情抉择）开发成可玩网页游戏的全过程产物。技术栈：React + TypeScript + Vite + Tailwind。

## 一、从设计文档到代码结构的映射

设计文档的每个章节直接映射为代码模块，做到"文档即规格"：

| 设计文档章节 | 代码位置 | 说明 |
|---|---|---|
| §3 武器类型/品质/强化/分解 | `src/game/data.ts` | 全部数值入常量表，不散落在逻辑里 |
| §4 经营/顾客/升级/声誉 | `data.ts` + `engine.ts` | 数据表 + 纯函数计算 |
| §5 剧情/好感/彩礼 | `src/game/scenes.ts` | 场景数据（说话人/台词/选项）与逻辑分离 |
| §6 多结局 | `data.ts` ENDINGS + `engine.ts` resolveEnding | 结局文案是数据，判定是函数 |
| §7 锻造等级/配方 | `data.ts` RECIPES/FORGE_LEVELS | 配方 = 类型×主材，三重门槛解锁 |
| §8 数值平衡 | `data.ts` DIFFICULTIES | 难度倍率表原样实现 |
| §10 UI布局 | `src/sections/*.tsx` | 每个标签页对应一个界面区块 |

## 二、分层架构决策

```
game/types.ts    纯类型（Weapon/Order/Customer/Scene/GameState…）
game/data.ts     纯数据（所有数值表，改平衡只动这里）
game/engine.ts   纯函数（锻造/定价/生成顾客/结局判定），无副作用，含种子随机
game/scenes.ts   剧情场景工厂（输入 state，输出 Scene 数据）
game/state.tsx   唯一可变层：useReducer + Context，action 即玩家操作，localStorage 自动存档
sections/*.tsx   界面层，只读 state + dispatch action
components/      UI 原语（像素面板/按钮）+ 场景播放器 + 结局屏
```

关键决策：

1. **场景系统是数据驱动的**：剧情不是散落在各处的 setState，而是统一的 `Scene { speaker, lines[], choices[] }` 结构 + 一个 SceneModal 播放器 + pendingScenes 队列。后期加"闲聊对话框"需求时，只需新增场景工厂函数并在 reducer 里 pushScene——一次迭代成本极低（这是真实发生过的需求）。
2. **剧情触发统一收口**：`checkTriggers(state)` 在每个改变营收/好感的 action 末尾调用，集中检查彩礼阈值、小铃事件、告白条件，避免触发逻辑散落各处。
3. **QTE 小游戏做成可复用组件**：`QTEPanel(modifier, onFinish)` 既用于锻造也用于铁匠大赛，修正值（心累 -10、护手 +10）以参数注入。
4. **状态即存档**：GameState 是纯可序列化对象，useEffect 监听变化整体写 localStorage；标题界面直接读取恢复。无需后端（单人游戏），但必须明确告知用户存档仅存在本浏览器。

## 三、数值矛盾的处理（重要经验）

设计文档存在内部矛盾：彩礼总额 338 万 G vs 单把武器售价 80~380G（按原文需锻造上万把，完全不可玩）。

处理方式：
- 不擅自改设计结构，而是引入单一**剧情缩放系数** `STORY_SCALE = 1/50`，只缩放彩礼相关金额，其余数值（材料价、售价、升级费、订单报酬、大赛奖金）原样保留；
- 难度倍率表（设计 §8.4）原样实现，缩放系数与难度倍率相乘；
- **主动向用户说明**这一改动及理由，而不是悄悄改掉。

教训：设计文档的数值表落地前必须先做"量级自洽性检查"——用文档自己的经济节奏章节（§8.3 反推单把收入）交叉验证，矛盾通常会在交叉验证中暴露。

## 四、美术与视觉

- 视觉方向先用设计参考检索工具确定：复古像素面板（脊线边框 + 硬阴影 + outset/inset 按压反转）+ 暖黄主色 `#fff1be` + 近黑文字 `#141312` + 锻造橙点缀，数字用像素字体（VT323），中文用系统字体栈。
- 横幅与两位女主头像由 AI 图像生成（像素风提示词），放 `public/assets/` 由 Vite 直接打包。
- 全局样式（像素面板/按钮/进度条/QTE 轨道/火花粒子）集中在 `src/index.css`，所有界面复用。

## 五、测试过程（无头浏览器全流程回归）

构建通过后，用真实浏览器工具按玩家路径逐步验证，而不是只看编译通过：

1. 标题画面渲染（截图目检）
2. 新游戏 → 开场剧情逐行推进 → 选项生效（好感+10、阶段推进）
3. 锻造：QTE 三阶段推进、材料消耗、品质判定、入库、HUD 更新
4. 开门迎客：顾客生成（**此处发现订单攻击要求过高的平衡 bug 并已修复**）
5. 市场采购：扣款、库存、仓库上限
6. 出售：报价滑条、成交、金币/总营收/议价联动
7. 社交：好感增减、精力消耗机制
8. 升级/日志页渲染
9. 存档：刷新页面后"继续游戏"出现，状态完整恢复

迭代修复记录：第一版社交互动只写日志无对话框 → 补场景演出（得益于场景系统数据驱动，改动很小）。
