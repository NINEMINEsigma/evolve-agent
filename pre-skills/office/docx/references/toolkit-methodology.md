# DOCX：Word 文档创建与编辑（通用版）

> 对应能力：专业 Word 文档的创建、编辑、批注、修订（tracked changes）、脚注、目录、Markdown 转 Word。

## 路由：看你手里有什么

**先记住**：纯文本读取（`read file`/`cat`）只能提取 `.docx` 的文字，所有格式信息丢失。任务涉及外观或结构时，必须用保留格式的解析方式。

**路线 1 — 编辑现有文档（格式重要）**：用户提供了模板、要修改/审阅/批注的文档，或任何格式需要保留或参考的文件。这个文件就是输出的基础——读它、改它、填它。编辑现有 `.docx` 一律走这条路；只有当文件仅作为数据来源（如参考文献、数据导出，格式无关紧要）时才直接提取文本。`.doc` 格式先转换：`libreoffice --headless --convert-to docx`。

**路线 2 — Markdown 优先**：已有完整 Markdown 是要转成 Word 的内容来源（用户明确要求 md 转 Word，或上游工作流交付了 md）。把 Markdown 当作最终内容源，直接转换，不要重启研究或改写正文。

**路线 3 — 从零创建**：既没有目标 .docx 也没有上游 .md。用代码从头构建（推荐 C# + OpenXML SDK 或 python-docx；要求高保真和复杂排版时用 OpenXML SDK）。

## 编辑路线硬规则

1. 编辑优先使用结构化的文档对象模型 API，不做临时性的 XML 拼接手术。
2. 大文档分窗口处理——不做超大块替换。
3. 出现警告或错误时，停下来重读，再继续。
4. 转换器的警告和错误是可操作的反馈：在副本上修复后重试，直到通过校验。绝不压制失败或把失败品当最终结果交付。

## 质量标准

**低饱和配色**：选一个色相方向，建三档——主色（标题）/深色（正文）/浅色（注释）。绝不用纯 #FF0000/#0000FF。封面文字颜色既要与背景有足够对比，又要与正文形成视觉区隔（更大字号、不同字重、充分留白）。

**封面/封底背景**：需要封面时从零生成独特背景（HTML/SVG + 无头浏览器渲染截图是一种可靠技术），用原创的图形与配色呼应文档主题。封面文字要构成独立的视觉空间，不是"放大的第一段"。

**内容约束**："X字左右"允许 ±20%。文件名按主题命名。全文所有元素语言一致。

## 交付检查清单

1. 文档能正常打开、无报错。
2. 所选路线的校验通过（OpenXML 结构校验/转换器校验）。
3. 用户或模板要求的页眉、页脚、页码存在且位置正确；长篇正式文档强烈建议加页码。
4. 无占位符残留（`[公司名称]`、`TODO` 等）。
5. 所有图片确实插入（构建日志显示图片数；若为 0 则图片未插入）。
6. 封面/封底文字与背景对比清晰可见。
7. 格式敏感的编辑，回读代表性区域，确认段内直接格式（含中英混排字体通道）符合预期——样式表改动不一定覆盖内联格式。
8. 大面积格式刷之前，先划定"保护区"（格式必须保持区隔的元素），完成后排除或复核。
