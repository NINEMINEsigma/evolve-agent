# pixbead — 拼豆式 CLI 像素画工具

工具本体：`scripts/pixbead.py`（单文件，唯一依赖 Pillow，仅 render 需要）。

## 三步工作流

```bash
python3 scripts/pixbead.py init art.pix --width 64 --height 48   # ① 初始化(默认全透明)
python3 scripts/pixbead.py pixel art.pix --set "3,4,#ff0000;5,6,#00ff00"  # ② 绘制
python3 scripts/pixbead.py render art.pix --out art.png --scale 12        # ③ 出图
```

画布文件 `.pix` 是纯 JSON（稀疏存储 `{"x,y": "#rrggbbaa"}`），每次绘制调用独立读写它。绘错随时重放：重新 init 后重放修改过的 ops 即可。

## 命令

| 命令 | 说明 | 关键参数 |
|---|---|---|
| `init` | 初始化画布 | `--width --height [--background]` |
| `pixel` | 按点赋色（拼豆模式），分号分隔多组 | `--set "x,y,color;x,y,color"` |
| `line` | 直线画笔，支持沿线渐变 | `--from --to --color/--colors --width` |
| `curve` | 任意阶贝塞尔曲线（De Casteljau），节点颜色沿曲线插值 | `--points "x,y;..." --colors "c1;..." --width [--steps]` |
| `rect` / `circle` | 矩形 / 圆 | `--origin --w --h` / `--center --radius`，`--fill` 填充 |
| `fill` | 洪水填充（需封闭区域） | `--seed --color` |
| `batch` | 从 JSON 一次执行多个操作 | `--ops ops.json` 或 `--ops -` 读 stdin |
| `render` | 渲染 PNG（RGBA 保留透明，最近邻放大） | `--out [--scale]` |
| `info` | 画布尺寸与已画像素数 | — |

## 颜色格式

- 命名色 20 个（`red` `blue` `white` `transparent`…）
- 十六进制 `#RGB` `#RGBA` `#RRGGBB` `#RRGGBBAA`（`#ffffff80` = 半透明白）
- 分量式 `r,g,b[,a]`（0–255）

颜色设为 `transparent` 即擦除该像素。

## 渐变语义（游戏引擎式）

`--colors "c1;c2;...;cN"` 的 N 个颜色对应曲线 N 个控制节点，画笔沿曲线行进时在相邻节点色间线性插值。直线同理，多个颜色均匀分布在整条线上。

## 批量模式（画复杂图案的首选）

逐点调用进程开销大，复杂图案用 batch 一次提交：

```json
[
  {"op": "pixel", "set": "1,1,#f00;2,2,#0f0"},
  {"op": "line",  "from": "0,0", "to": "10,10", "color": "#00f"},
  {"op": "curve", "points": "0,0;8,16;15,0", "colors": "red;yellow;blue", "width": 2},
  {"op": "fill",  "seed": "5,5", "color": "#123456"}
]
```

单个 `pixel` op 的 `--set` 串建议每 800 个像素分一个 op。

## 绘制像素角色/复杂图案

不要把角色拆成逐点手工绘制——用 Python 生成器把造型（多边形、椭圆、外轮廓描边）栅格化成像素集，导出 batch JSON 再交给本工具执行与渲染。完整模式（形状辅助函数、图层顺序、外轮廓自动描边、迭代修正方法）见 [references/pixel-art-workflow.md](references/pixel-art-workflow.md)。

渲染检查用 `--scale 6`~`12` 放大目检；发现局部问题后只重画出错区域并重新提交 ops，不必从头返工。

## 质感：像素画 vs 矢量感

出图后如果被评价为"像 SVG""像矢量图栅格化"，原因通常是以下两条。

### 1. 逻辑画布太大、放大倍数太小

像素感来自**单个逻辑像素在成图中的物理尺寸**，不是分辨率高低。

| 逻辑画布 | 放大 | 单元尺寸 | 观感 |
|---|---|---|---|
| 256 × 256 | ×4 | 4 px | 像低分辨率照片，像素感弱 |
| 128 × 128 | ×8 | 8 px | 明确的像素画方块感 |

同样的 1024 输出，优先选 128 画布 + ×8。

### 2. 渐变用了逐像素线性插值

连续插值会产生上百种颜色，看起来像 SVG 渐变被栅格化。正确做法是**限色 + 色带化 + 交界处抖动**：

```python
BAYER4 = ((0, 8, 2, 10), (12, 4, 14, 6), (3, 11, 1, 9), (15, 7, 13, 5))

def ramp_dith(stops, t, x, y, soft=0.18):
    # 每个色阶内平涂纯色，只在交界处留 soft 比例的窄抖动带
    ...
```

- `soft≈0.15~0.20` 推荐；`soft=1.0`（全程抖动）会让大面积区域布满网点像纱窗，是反面效果
- 细节元素（线条、飞鸟、印章笔画）必须纯色单像素，不参与抖动
- 唯一颜色数控制在 20~40；超过 40 说明渐变没量化

### 3. 完美几何需要扰动

纯数学弧线、笔直斜边即使加了抖动也仍有矢量味。给轮廓加低幅噪声（±1 px）、让弧线半径逐点抖动、用噪声打断长线，即可打破。

### 4. 抖动矩阵的物理尺度决定成败

Bayer 4×4 的网点周期是 4 个逻辑像素。`--scale 4` 时它变成 16 屏幕像素的**规则网格**，远看是"半调印刷/纱窗"——水墨、雾、云、天空这类大面积淡墨题材最容易死在这里。

按题材选抖动方式：

| 题材 | 抖动方式 |
|---|---|
| 色块平涂为主的图形 | Bayer 有序抖动（窄交界带，`soft≈0.15`） |
| 大面积淡墨 / 雾 / 云 / 天空 | 团状随机阈值 `0.6*vnoise(x*0.21,y*0.21) + 0.4*hnoise(x,y)` |

配套做法：把"浓度 → 颜色"拆成两段——低浓度区用概率点阵（覆盖率 = 浓度，模拟墨化开的颗粒），中高浓度区直接平涂色阶。**让 70% 以上的像素落在平涂区**，网格感才会消失。

完整范例 1 —— [examples/fuji-seigaiha/](examples/fuji-seigaiha/)：浮世绘富士山 + 青海波，128×8 出 1024，24 色 37 op，含成品图、生成器脚本、构图坐标表、以及四条死路（高度场画浪必然画成山、等宽管道、泡沫爪画成白香肠、256×4）的失败分析。

完整范例 2 —— [examples/ink-landscape/](examples/ink-landscape/)：水墨山水（宽幅 16:9），400×225 ×4 出 1600×900，12 色 46 op。演示浓度场渲染（8 阶墨 + 概率点阵两段映射）、显式山脊控制点、三层山叠压与云团遮挡、放射状松针，以及五条死路（幂律山形画成锯齿、Bayer 铺淡墨成屏幕门、700 条皴线画成毛皮、中山等距起伏成剪刀、瀑布画成劈山白柱）的失败分析。

完整范例 3 —— [examples/sunset-sky/](examples/sunset-sky/)：黄昏天空横幅，128×96 ×4 出 512×384，57 色 57 op。演示"多瓣并集定轮廓 + 全局高度场定明暗"的云画法（避免葡萄串）、天空斜纹的三个收敛参数、海面横向色带，以及**卷浪 10 版全部失败的完整复盘**与非整除尺寸的处理方案。

## 什么时候该放弃一个元素

有机立体形体是生成器范式的盲区。动笔前先判断元素属于哪一类：

| 可以用场/函数描述 | 必须手摆像素 |
|---|---|
| 云、雾、天空渐变（团块 + 高度场） | 卷浪、织物褶皱、手指 |
| 山体（山脊控制点 + 深度衰减） | 有遮挡的复杂有机体 |
| 水面（横向色带 + 波纹） | 需要"立体感 + 不规则泡沫"的东西 |

两条硬规则：

- **迭代 3~4 版仍不达标 = 方法错了，不是参数错了。** 立刻停手换方法或砍掉该元素，不要继续微调参数。
- **砍掉往往让画面更好。** [examples/moonlit-pond/](examples/moonlit-pond/) 删掉画不好的人物、[examples/sunset-sky/](examples/sunset-sky/) 删掉画不好的卷浪，两次都是删完之后画面立刻达标。

## 画人物：先判断值不值得

人物是高成本元素，像素预算消耗大，任何一处比例或五官失准都会被立刻察觉。动笔前先确认画布够不够：

| 画布宽度 | 头高 | 可用眼高 | 结论 |
|---|---|---|---|
| 128 | ~11 px | 2 px | 画不了人，改画景物 |
| 160 | ~14 px | 2–3 px | 五官会糊成一团 |
| 240 | ~33 px | 7–8 px | 勉强可画 4 头身，能做出动漫眼 |

经验阈值：**画布宽度低于 200 px 不要画人物**。

若决定要画，几条硬约束：

- 头发必须**先画、贴背侧**，宽度 ≤ 头宽 × 1.2（超过会把身体吞成一块白色）
- 脸型用 14 点左右的多边形，上宽下窄收尖下巴；正圆会读成方块脸
- 刘海要**把额头区域所有肤色像素替换成发色**，用环形多边形会留下空白额头（秃头感）
- 动漫眼 = 杏仁眼白 + 三层虹膜 + 瞳孔 + 虹膜下缘反光 + 左上高光 + 粗黑上睫毛（外眼角上挑）
- 夜景双光源时，左右边缘光颜色必须分开（冷月光 / 暖灯光），否则深色衣服会糊进背景

完整人物画法与像素预算表见 [examples/moonlit-pond/](examples/moonlit-pond/)。该范例还记录了一个重要决策：人物迭代 6 版仍不达标，最终**整块删除改为纯景物**，画面质量立刻达标 —— 景物元素容错率高得多，若人物反复修不满意，果断删掉比继续修补划算。
