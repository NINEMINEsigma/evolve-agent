# 样例 03：像素风列车过境（黄昏背光，3 秒）

## 用途

低分辨率像素风的电影感镜头：固定侧视机位，一列电力动车从右向左疾驰，中途把落日整块挡住。远景群山、近景草木随风摆，光用丁达尔光柱表现。

适用于：游戏过场、复古向片头、产品叙事里的「旅途 / 时间流逝」过渡、需要"手工像素"质感但不想逐点手绘的项目。

**画面全部由代码生成**：素材用 `gen_assets.py` 栅格化成 batch ops 交给 pixbead 渲染成 PNG，动画在 Remotion 里做。

## 规格

| 项 | 值 |
|---|---|
| 逻辑画布 | 320 × 180（16:9） |
| 放大倍数 | ×6 → 1920×1080（每个逻辑像素 = 6 屏幕像素） |
| 时长 / 帧率 | 3.000s / 180 帧 @60fps |

## 素材生成（pixbead 工作流）

`gen_assets.py` 不做逐点手绘，而是把造型栅格化成像素集，导出 batch ops JSON，再由 pixbead 执行与渲染：

```
① init  → 建 320×180 画布（默认透明）
② batch → 一次提交所有 pixel op（每 800 个像素一个 op）
③ render → --scale 1 出逻辑尺寸 PNG（放大由 Remotion 用 image-rendering: pixelated 完成）
```

14 张图层的像素量：天空 44,160 / 山 8,187 / 地面 13,440 / 云 9,910 / 列车 9,978 / 草与芦苇各 150~790。

**渐变必须色带化**：天空用 11 个 stop，每个 stop 之间只留 34% 宽的抖动过渡带（Bayer 4×4），其余平涂。全程线性插值会产生上百种颜色，看起来像矢量图栅格化。

## 关键技术点

### 1. 列车必须够高，否则挡不住太阳

第一版太阳在 y=46（高空）、车顶在 y=112，**几何上根本碰不到**。重排后：

```
太阳       y=109..123（r=7，贴地平线，落在远山上方）
列车车顶   y=112        ← 覆盖太阳的 112..123，只在顶上漏一线光晕
列车车底   y=140        ← 压在钢轨 y=140..141 上
```

结论：**「列车挡住太阳」是一个垂直布局问题，不是动画问题**。太阳必须压到地平线附近，列车的高度范围必须与太阳的垂直区间重叠。

### 2. 「完全贯穿左右」需要车长 > 画面宽

```
画面宽 320，车长 460 → 贯穿窗口 = 460 − 320 = 140px
速度 245 px/s → 贯穿持续 140/245 ≈ 0.57 秒（落在 1.45s ~ 2.02s）
```

车长小于画面宽时，任何时刻都至少有一侧是空的，**不可能出现贯穿**。速度太快会让贯穿时间短到看不清，太慢又不像"疾驰"——0.5~0.7 秒是能看清又是冲刺感的区间。

起点 x=330（车头在右边界外），3 秒后车头到 −380、车尾停在 x≈80，所以结尾左侧还压着半截车身。

### 3. 丁达尔光柱：用光被切断表现遮挡

不用整体压暗（那样像曝光变化，不像被遮）。做法是每帧在 320×180 的 canvas 上重画光柱：

```ts
for (const angle of RAYS) {              // 11 道，角度 −88° ~ +32°
  for (let d = 5; d < 175; d += 3) {     // 沿射线每 3px 一个像素块
    const x = SUN_X + sin(angle) * d, y = SUN_Y + cos(angle) * d;
    if (blocked(x, y)) continue;         // 被列车挡住 → 这一块不画
    const w = 1 + Math.floor(d / 34);    // 越远越宽
    const a = 0.68 * (1 - d/178)^0.8 * (1 - occlusion*0.92) * breathe;
    ctx.fillRect(...);                   // 外圈暖黄 + 芯部亮色
  }
}
```

- `blocked()` 判断像素是否落在列车矩形内 → 光柱**在列车轮廓处自然断开**
- `occlusion` 是太阳被遮的水平重叠比例，被遮时整束衰减 92% —— 于是"草地上的光带"随列车经过而熄灭、随列车离开而恢复
- 每 3px 断一格 + 12% 概率跳空，形成光里浮尘的断续感

### 4. 风的整数位移

草与芦苇各分 3 个变体层（生成时按 `i % 3` 分配），Remotion 里各层用不同相位：

```ts
const sway = (phase, amp) => Math.round(Math.sin(t * 2.35 + phase) * amp);
```

`Math.round` 是关键：位移取整后再乘 6，永远落在屏幕像素网格上，不会出现半像素模糊。列车在画面内时，近景草与芦苇再额外向右偏 2px（气流方向）。

### 5. 云的画法

参考「团块并集定轮廓 + 高度场定明暗」，但纯椭圆并集会僵：

| 手段 | 实现 |
|---|---|
| 不规则轮廓 | 每个椭圆的半径按极角调制：`wob = 1 + 0.20·sin(3θ+i) + 0.11·sin(5θ−2i)` |
| 破碎边缘 | 边缘区（membership < 0.12）50% 概率缺一块 |
| 内部层次 | 4 个"裂隙椭圆"压暗 0.22 档，而不是挖穿（挖穿会露出天空，看起来像黑瘤） |
| 明暗 | `bright = 0.25·(1−离太阳距离) + 0.75·(高度)` —— **高度是主因**，夕阳从下方照亮云底 |
| 颜色 | 6 阶：深紫灰 → 紫 → 粉紫 → 橙粉 → 黄橙 → 亮黄白，交界 Bayer 抖动 |

两个小云放在 x≈168/187 处做纵深，大小约为大云瓣的 1/3。

### 6. wind 的其他表现

- 云层整体缓慢左移（1.4 px/s，取整）
- 18 个暖色尘埃粒子自右向左飘，越靠前越快（46~124 px/s），带正弦上下浮动
- 太阳周围的光晕用概率点阵（密度随距离衰减），不是平滑渐变

## 复用方式

1. **换时段**：改 `SKY_STOPS` 与 `CLOUD_STOPS` 两组色表，其余逻辑不变（清晨=冷蓝粉白，夜晚=深蓝紫 + 月亮当逆光源）
2. **换列车**：只改 `build_train()`（车长、车窗数、转向架数量），同步改 `PixelTrainScene.tsx` 的 `TRAIN_W`
3. **要更快 / 更长**：改 `SPEED`，贯穿时长 = (车长 − 画面宽) / SPEED，建议控制在 0.5~0.7s
4. **要更粗的像素**：把逻辑画布降到 240×135、放大倍数提到 8，同时按比例缩小所有坐标（本样例全部按 320×180 设计）
5. **换成竖版**：逻辑画布 180×320，太阳与列车的高度关系需要重新算

## 已知取舍

- 云用椭圆并集 + 极坐标扰动，**能出蓬松感但出不了卷云那种丝状细节**；需要的话得改用噪声场 + 分层绘制
- 草是 1px 直线笔画，密度高时会近似"毛刷"；本样例控制在 66 株中景 + 39 株近景
- 列车是纯剪影 + 单侧轮廓光，没有车体细节（受电弓、车窗是唯一的"信息"）；这是像素风远景的合理简化
- 光柱是逐像素块绘制，列车贯穿时每帧约 2000 次 `fillRect`；画布只有 320×180，单帧开销可忽略，但如果把逻辑画布提到 960×540 需要重新评估
- 太阳的遮挡比例只看水平重叠，没做垂直方向判断——因为列车的高度区间完整覆盖太阳，水平重叠足够判定
