# 样例 02：城市体积模型档案界面（City Archive）

## 用途

俯视白模城市 + 档案系统 HUD 的数据可视化镜头。8 秒，约 3000 栋白模建筑、地面投影阴影、红色标注层、ARCHIVE 风格界面。

适用于：档案/监控/普查类叙事、数据体量可视化、"系统正在扫描某片区域"的过场、需要俯视城市但不想用实拍素材的项目。

## 为什么这座城要用 Canvas 画

先按 SVG 逐元素实现过一版，结论是撑不住：

| 维度 | SVG 逐元素 | Canvas 2D |
|---|---|---|
| 建筑尺度 | 单栋顶面菱形宽 = 1.732 × U，U=95 时 165px，画面像"巨型方块特写" | U=38 时 66px，接近俯视城市实感 |
| 所需数量 | 缩到 66px 需 62×62 网格 ≈ 3000 栋 | 同左 |
| 每帧元素 | 3000×3 = 9000 个 `<polygon>`，React 逐帧 diff + Chrome 重建 | 9000 次 `ctx.fill`，无 DOM |
| 阴影 | 3000 个独立 polygon | 3000 个四边形合并成**一条 path**，一次填充 |
| 实测 | 单帧数秒且内存持续增长 | 单帧 0.5–1 秒（1080p，4 并发），8 秒成片约 1.5–2 分钟 |

结论：**几何体量上千就一定走 Canvas**；HUD 文字留在 HTML 层（字形锐利、排版好调、不用管 canvas 字体加载）。这是本样例最重要的结构决定。

## 几何：投影与覆盖

### 等距投影（含绕竖直轴旋转）

```
xr = x·cosφ − y·sinφ          // 世界坐标绕竖直轴旋转 φ
yr = x·sinφ + y·cosφ
sx = (xr − yr) · cos30°
sy = (xr + yr) · 0.5
```

高度 h 不参与上面的旋转，只沿屏幕 −y 方向单独施加：`sy' = sy − h·f`。

**这样做的关键差别**：旋转作用在世界平面上、高度单独施加，所以建筑竖直边在屏幕上**永远垂直**——这是"相机绕场景转"，而不是"把画面转一下"。后者在小角度下也许看不出，一旦角度超过 5° 会立刻露馅（整座城像纸片）。

### 覆盖条件（必须算，否则边缘露白）

菱形网格边长为 `L = N·U`，投影后 sx 范围 `±0.866L`、sy 范围 `±L/2`。要让菱形包住画布四角 `(±960, ±540)`：

```
960/(0.866L) + 540/(0.5L) ≤ 1
(1108.5 + 1080) / L ≤ 1
L ≥ 2189            // 1080p 下的下限
```

本样例取 `N=62, U=38 → L=2356`，留出旋转与平移余量。**这一条是踩过的坑**：只按画布上下边（540）算会漏掉四角，画面底部两块空地就是这么来的。

### 透视

`f = 1 + PERSP · sy / (L/2)`，`PERSP = 0.09` 时远处缩到 0.91、近处放到 1.09。透视系数同时作用于水平位移和高度缩放，建筑的竖直边依然垂直（只是长度随深度变化），几何上自洽。

## 城市生成规则

| 规则 | 取值 | 效果 |
|---|---|---|
| 街道 | `gx % 7 === 0 \|\| gy % 7 === 0` 的格子跳过 | 形成 6×6 的街区网格，这是"城市感"的主要来源 |
| 街区内空地 | 10% 概率跳过 | 广场、停车场，避免过于机械 |
| 占地面积 | 86% 为 1×1，12% 为 1×2 / 2×1，2% 为 2×2 | 体量错落 |
| 高度 | `unit = 0.35 + pow(rand, 2.4) × 2`，`h = unit · U` | 幂函数让绝大多数建筑偏矮，少数中高 |
| 高塔 | 4% 概率 `unit × 2.2` | 天际线有峰值，不会一片平 |

全部用 `random("seed-string")`（Remotion 内置确定性随机），同一工程任意次渲染结果一致。

## 阴影

每栋建筑向世界 `+x/+y` 方向（屏幕右下）投出长度 `h × 0.4` 的四边形，**3000 个四边形合并成一条 path 后一次 `fill`**：

```ts
ctx.beginPath();
for (const b of CITY) { /* moveTo / lineTo ×4 */ ctx.closePath(); }
ctx.fillStyle = "rgba(148,156,167,0.19)";
ctx.fill();
```

顺序上阴影整体画在建筑之前。物理上近处建筑的影子会被远处建筑盖住，但在等距俯视 + 低层城市里视觉上不可见，换来的是几百倍的性能提升。

## 红色标注层

三层，都在同一投影坐标系里计算，所以自然贴合城市网格：

| 层 | 实现 | 时间 |
|---|---|---|
| 贴地红块 | 世界平面上的正方形四角投影成平行四边形，`fill rgba(200,22,35,0.17)` + `stroke rgba(200,22,35,0.5)` | 1.5s 起逐个展开，每个 0.5s |
| 红点 | `arc()` 实心圆 + 外圈描边，半径随出现进度 `p` 放大 | 1.1s 起每 0.08s 一个 |
| 跨屏斜线 | 屏幕空间 `rotate(-27°)` 后一组平行 line，每 3 条加深 | 2.5–4.0s 渐显 |

红块用世界坐标而非屏幕坐标，是为了让它们"躺"在城市地面上，随运镜一起动。

## 质感层

| 层 | 参数 | 作用 |
|---|---|---|
| 暗角 | 径向渐变，0.72 处 16% 白、边缘 68% 白 | 边缘渐白，模拟远景雾，同时把画面边缘收住 |
| 色差 | 线性渐变，左 `rgba(200,22,35,0.055)` → 右 `rgba(28,95,138,0.05)` | 极淡的红/青色偏，像旧镜头 |
| 噪点 | 256×256 确定性噪点 canvas 平铺，`globalAlpha 0.05` | 消除大面积白色的"塑料感"，避免 h264 压出色块 |

噪点用预生成的贴图平铺，而不是每帧 `createImageData`：既快，也保证多帧之间颗粒不闪。

## 运镜

8 秒内只有三个量在动，幅度都很小：

```ts
spin:  -0.028 → 0.021 rad   // ≈ −1.6° → +1.2°
zoom:  1.000  → 1.075
panX:  -14 → 10 ,  panY: 9 → -7
```

因为旋转幅度只有 ±1.6°，深度排序**不必每帧重算**，在模块加载时按 `gx+nx+gy+ny` 预排序一次即可，省下每帧 3000 次排序开销。

## 改造建议

- **要更密/更疏的城市**：调 `U`（建筑尺度）与 `STREET`（街区大小）。改 `U` 后必须重新检查 `N·U ≥ 2189`，否则边缘露白
- **要更高的楼**：把高度公式里的 `2` 提到 `3` 或把高塔概率 `0.96` 降到 `0.92`
- **要正等距而非透视**：`PERSP = 0`，画面立刻变成"技术图纸"感
- **要夜间版本**：背景渐变改深色、建筑顶面降到 `#8a9098`、红块提高不透明度，暗角改为黑色
- **要静态数据图**：把 `spin/zoom/pan` 全部写死为常数，`DURATION` 只影响红块/红点的展开节奏

## 已知取舍

- 深度排序用**旋转前**的深度预排序。旋转超过约 ±5° 时相邻建筑的遮挡可能出现错位，届时应改为每帧按旋转后 `sy` 排序（成本约每帧 3000 次 sort）
- 阴影不做柔边模糊：`ctx.filter = "blur(...)"` 在这个体量下会让单帧时间翻几倍，改用低不透明度 + 建筑自身的面明暗差表现体积
- 红块数量与位置是确定性的随机分布。若要"精确框选某几栋楼"，应改为按网格坐标手工指定，而不是随机
- 画面里没有真实地理数据，是程序化虚构城市。若需要真实城市轮廓，应换用真实底图 + 城市体块数据
