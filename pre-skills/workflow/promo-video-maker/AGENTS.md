# 本地化视频制作器 · 工作规范

本规范把原始 `ai-promo-video-maker` 的 Remotion 制作方法适配到 Windows 与 Evolve Agent，并吸收两个已完成视频项目的验证经验。

## 最高目标

先把内容讲对，再把画面做清楚，最后用可复现的工程和质量闸门交付。宣传片要让陌生观众理解产品价值；研究/教学视频要让观众理解概念。不能用宣传片模板替代内容设计。

## 四条总原则

1. **先确认再制作。** 需求确认、风格样帧、声音方案、素材边界和导出规格必须写入 `需求确认.md`，主人明确确认后才开始改工程。
2. **风格服务内容。** 每个主题重新选择视觉方向。研究/教学视频可以使用公式、SVG、流程图和数据图；宣传片优先展示真实界面、真实作品和可核实数据。
3. **讲人话且不编造。** 第一屏说明“这是什么、为什么重要”。每个数字、功能、案例和来源都要可核实；不确定就写“不知道”或删掉。教学示意必须标明不是实测数据。
4. **所有关键阶段都有闸门。** 代码、内容/数学、关键帧、字幕、网页、音频和成片分别检查；发现问题就修复后重跑，不用一句“看起来没问题”代替验证。

## 运行环境与路径

本机是 Windows。命令和脚本必须满足：

- Python 命令使用 `python`；npm 使用 `npm.cmd`。
- 不使用 Bash 管道、`mkdir -p`、`tee`、`/tmp/` 或 Unix 专有命令作为必需步骤。
- Node 脚本使用 `fs.mkdirSync(..., {recursive:true})`，渲染日志用 Node 文件流保存，并把子进程退出码传回。
- 绝对路径通过 Shell 的环境变量传递；文件读写使用当前工具的 `Read`、`Write`、`PatchEdit`、`Copy` 等专用工具。
- 不启动或修改 Evolve Gateway。Gateway 地址、端口和其他启动参数由运行时系统提示词提供，不能在技能中写死、推断或复述为固定值。工程网页服务使用单独的临时端口：优先读取 `PROMO_WEB_PORT`，否则由启动脚本选择空闲端口。
- 项目文件放在 `ws:projects/<项目名>/` 或主人明确指定的项目目录。技能目录只放规则、模板、参考和脚本，不放成片、缓存、密钥或 `node_modules`。
- 网页部署资源使用相对路径；Session Site 入口必须是实际 `/files/ws/sessions/<会话>/site/index.html`，不可把 `ws:` 直接写入 HTML `src` 或 Markdown 链接。临时播放器地址以 `serve.mjs` 输出的实际地址为准。

## 项目模式

### 宣传片模式 `promo`

保留原始仓库的产品宣传片原则：开头 3 秒出现痛点或亮点，真实产品素材为主角，高潮处放 CTA，配乐/旁白需要试听拍板。默认 45~60 秒，超过时长需说明理由。

### 研究/教学模式 `research` / `teaching`

不强制真实截图数量、CTA、产品网址、快切蒙太奇或商业旁白。优先：

- 一个贯穿全片的核心问题或可视化主角；
- 公式、数据和示意图可核算；
- 每个概念有足够阅读时间；
- 字幕和画面表达同一叙事；
- 引用、事实和教学简化明确区分。

## 声音与字幕模式

`src/timing.json` 应含：

```json
{
  "mode": "research",
  "audio": {"mode": "silent"},
  "subtitles": [
    {"id":"intro", "at":0, "end":4, "text":"这里放字幕"}
  ]
}
```

允许的音频模式：

- `silent`：不加载 `mix.wav`，网页不创建 `<audio>`，成片允许没有音轨。
- `music`：加载配乐/音效，运行 `mix.py` 产出 `public/audio/mix.wav`。
- `voice`：在 `music` 基础上生成旁白，`vo` 和 `check-mix` 全部通过后混音。

字幕可以直接由场景渲染，也可以由 `scripts/srt.py` 导出独立字幕。无旁白时，字幕不是音频转写，而是独立交付文本，必须检查时间窗和阅读速度。

## 需求确认

使用当前 `Ask` 工具时遵循“简短 question + 详细 detail”：标题只写一个短句，选项解释、推荐理由和表格放 `detail`。宣传片至少确认交付形式、画幅/时长、受众、风格样帧、叙事、高潮/CTA、素材版权、声音、导出和网页版；研究/教学视频至少确认主题/报告、受众、时长、画幅、视觉、字幕、声音、数学深度和交付物。

用户回答“你来决定”时可以拍板，但必须把决定和理由写进 `需求确认.md`。没有明确确认不得开始制作。

## 完整流程

### 0. 回看经验与环境体检

先读取 `references/踩坑记录.md` 和对应的需求、素材、音乐、配音、校验文档。执行：

```powershell
python template/scripts/doctor.py
```

建好工程后，在工程目录再次执行：

```powershell
python scripts/doctor.py
```

体检脚本只检查，不擅自安装；缺依赖时向主人报告，获得同意后再安装。

### 1. 预调研

宣传片核实产品官方状态、目标用户、真实页面、作品、数据和版权；研究视频读完报告，列出核心论点、公式、数字、争议点和可信来源。报告中的错误表述不能照抄。

### 2. 需求与风格样帧

做 3~4 个彼此明显不同的方向；研究视频可以用 Remotion/HTML/SVG 画样帧。样帧只用于让主人选择，不代表最终镜头已经确定。将结论写入 `需求确认.md` 并等待确认。

### 3. 创建工程

新工程始终从模板复制，不复制旧项目：

```powershell
# 使用文件工具 Copy；随后在工程目录
npm.cmd ci --no-audit --no-fund
```

安装依赖前确认项目目录和安装许可。不要在技能模板目录运行 `npm install`、`fonts`、`mix` 或 `render`。

### 4. 统一时间轴

`src/timing.json` 是动画、字幕、音乐、旁白和校验的单一事实源。时间使用秒，帧数统一通过 `Math.round(duration * fps)` 得出，避免浮点误差。场景组件接收绝对时间 `t`，窗口外返回 `null`。

### 5. 视觉实现

共享 `src/lib/theme.ts`、`src/lib/anim.ts`、字体和通用组件；每个场景一个组件。用 `ramp`、`keys`、`impulse`、`shake`、`typed` 和 `beatAt` 做确定性动画。图片始终按原比例显示，不能只给高度再依赖 `max-width`。

### 6. 素材、字体和音频

- 字体：修改 `fonts.json` 后执行 `npm.cmd run fonts`，检查缺字。
- 图片：记录路径、URL、归属和场景。大型图片按实际显示尺寸准备，避免 4K 同屏解码失败。
- 网页截图：优先 `scripts/shot.py`；登录使用独立有界面窗口；已在内置浏览器登录则用 `snapshot.js` + `snapshot.py` 重新渲染。
- 宣传片：遵循原参考文档的真实素材与试听规则。
- 研究/教学：音频可为 `silent`，不因缺少 `mix.wav` 强行创建声音；如果用音乐或旁白，仍需做波形、响度和转写检查。

### 7. 校验顺序

在工程目录按顺序执行：

```powershell
npm.cmd run lint
npm.cmd run test:content
npm.cmd run fonts
npm.cmd run check:assets
npm.cmd run stills -- --scenes --scale 0.5
npm.cmd run sheet
npm.cmd run render:preview
npm.cmd run web:build
npm.cmd run render:1080
npm.cmd run validate:video -- out/final-1080p.mp4
```

若项目没有某个可选脚本，不要伪造“通过”；在校验记录里标注“不适用”或“未执行”。

关键帧和联系表检查：

- 文字无外溢、截断、意外换行或遮挡；中文标题不要在词中间断行。
- 数字、名称、网址与调研笔记一致。
- 每段字幕有足够停留时间；底部字幕不遮挡关键图形。
- 研究视频允许低动态阅读停留，但不能有完全不变的错误帧；用实际帧差复核。
- 转场不黑屏、不闪错帧；网页截图不被横向压扁。

成片校验至少包括：

- `ffprobe`：宽、高、帧率、帧数、时长、编码和音轨是否符合需求；静音模式明确允许零音轨。
- `ffmpeg -v error -i video -f null -`：全片解码无错误。
- 黑帧检查；低动态告警需要联系表和帧差复核。
- 有音频时：响度、真峰值、音轨数量、音频时钟和旁白转写；无音频时：确认确实没有音轨。

### 8. 网页播放验证

网页构建后使用相对路径和实际服务地址。优先 Browser 工具检查：

1. 页面标题、正文和播放器容器存在；
2. 资源请求成功，无模块 MIME 错误；
3. 播放、暂停、跳转、结束状态和重播行为；
4. 有音频时用普通 `<audio>` 作为时钟，画面跟随音频；无音频时使用**经过时间 × FPS**计算当前帧，不能用每个 `requestAnimationFrame` 简单加一；
5. 静音模式同时断言：成片无音轨、网页无音频资源请求，并设置 Remotion Player 的 `numberOfSharedAudioTags={0}`，避免内部空音频标签干扰检查；
6. 播放暂停后继续时保存当前帧/音频位置，不能从零或错误帧续播；
7. 移动宽度下布局不溢出；
8. 测试结束立即暂停并关闭测试页面。

网页服务端口不要写死：使用模板的 `scripts/serve.mjs`，通过 `PROMO_WEB_PORT`/`PROMO_WEB_HOST` 配置，未指定时让操作系统选择空闲端口；浏览器使用脚本输出的实际 URL。不要把运行时系统提示词中的 Gateway 参数复制到项目或 Skill。

字体资源使用相对路径（例如 `./fonts/PF-Regular.woff2`），确保网页放在 Session Site 或其他子目录时仍能加载。

预览必须是真正的低成本预览：模板 `render.mjs --preview` 同时使用较低 FPS Composition 和 `--scale=0.5`，不能只降低 FPS 而保持正式分辨率。

### 9. 交付与改版

项目固定包含：

```text
<项目>/
├── 成片.mp4
├── 字幕.srt（有字幕时）
├── 需求确认.md
├── 调研笔记.md 或 事实核对.md
├── 校验记录.md
├── 网页版/
└── 工程/
```

工程内的 `out/` 保存关键帧、联系表、日志和版本备份。正式文件不散落在 `ws:` 根目录。

改版时先备份旧 MP4 和网页，更新 `需求确认.md` 修改记录；只改声音可以换音轨，不必重渲染画面；改场景、分镜或字幕需要重跑关键帧和成片闸门。

## Windows 命令与网页注意事项

- `npm.cmd` 在 PowerShell 中比直接调用 `npm` 更稳定。
- 使用 `scripts/render.mjs` 替代 Bash `tee` 管道，确保渲染失败不会被管道吞掉。
- 使用 `encodeURI` 或相对文件名处理中文下载链接。
- `web/vite.config.ts` 配置 `base: './'`，`web/main.tsx` 的字体路径使用 `staticFile` 或相对资源路径。
- `web:serve` 使用 `PROMO_WEB_PORT` 指定的临时端口，未指定时由启动脚本选择空闲端口；不要读取、修改或假设 Gateway 的运行时参数。
- 不把 `<video>` 与网页音频同时播放；只打开一个播放源。
