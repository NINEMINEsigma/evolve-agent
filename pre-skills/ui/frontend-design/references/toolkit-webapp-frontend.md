# Web 前端构建（通用版）

> 对应能力：构建现代 React Web 应用——复杂 UI 组件与状态管理、落地页、网站复刻；信息图/海报也可做成网页形态。

## 技术栈

React + TypeScript + Vite + Tailwind CSS + shadcn/ui（40+ 预装组件，含全部 Radix UI 依赖、路径别名 `@/`、生产构建优化）。

## 工作流

1. **初始化**：用脚手架脚本生成完整项目（可带模板：模板项目的内容集中在 `src/config.ts`，改配置即可，不要动组件文件）。
2. **开发**：页面区块放 `src/sections/`，自定义 hooks 放 `src/hooks/`，类型定义放 `src/types/`。
3. **构建**：`npm run build` 产出 `dist/`（tree-shaking、代码分割、资源压缩、hash 缓存）。

调试循环：改源文件 → 构建 → 检查 `dist/`。

## 关键工程规则

- 第三方库先 `npm install` 再 `import`——漏装依赖或漏导入会导致白屏。
- 静态预览无服务端重写：所有路由必须能从 `/` 到达（hash 路由或应用内导航），直接访问子路由会白屏。
- 路由根组件（BrowserRouter）只挂载一次，不要在子组件重复包裹。
- 构建失败时修上游原因（重装依赖、修源码错误），不要改构建脚本绕过。
- 不要假设用户提到的图片/附件存在——先检查上传目录，缺失就告诉用户并请其上传。

## 交付与预览（按宿主平台机制）

- 平台若提供版本保存/预览机制：保存版本即交付，平台渲染预览卡片。保存成功但用户看不到预览时，基本是平台侧问题——最多重存一次，建议稍后重试，不要反复重建。
- **预览 ≠ 发布**：不要把"版本已保存"说成"已上线/已发布"，除非平台确实完成了独立的发布动作。
- 只给用户平台实际返回的地址——绝不构造、猜测或"验证"另一个链接。

## 数据持久化的诚实原则

- **需要真实后端的信号**：跨访问保存记录、用户账户/登录、提交、预订、订单、多用户共享数据——这些都要求全栈（见 `webapp-backend.md`）。
- **纯前端**：数据最多存浏览器 localStorage。绝不要把 localStorage 或 mock 数据当作真实持久化呈现；选择纯前端时明确告诉用户：数据只存在当前浏览器，清缓存即丢失、不跨设备同步。
