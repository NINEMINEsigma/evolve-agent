## 1. 目标与边界

mod 是面向 Evolve Agent 的系统功能指导。它解释某项功能如何使用、何时使用、限制及相关功能入口，不是可执行插件，也不是功能本身。

目标：

1. 将非必要常驻的功能说明从系统提示词中逐步移出，需要时再加载正文。
2. 沿用技能的主要交互方式：先发现名称与简介，再通过工具把完整指导带入当前上下文。
3. 一次工具调用支持多个 mod，并由程序在内部递归加载其全部必需依赖，不让 Agent 为每层依赖重复调用工具。
4. 公共依赖在同一次调用中只输出一次；普通关联不触发无边界的自动扩展。
5. 指导内容能够使用受控运行时占位符，正确区分当前子会话与资源所属主会话。
6. 加载过程只读取受信任的本地文档，不执行脚本、不访问网络、不自动启用功能或工具集。

首版不包含：mod 安装市场、远程依赖下载、版本范围求解、脚本钩子、任意模板执行、自动修改文件、自动模型调用，以及基于关键词的隐式全文加载。

加载 mod 不扩大工具可用范围、沙盒权限或审批授权。系统基本约束与模式必需协议不能依赖 Agent 先加载某个 mod 才成立。

## 2. 当前实现与可复用部分

当前代码中尚未发现 `RecallMod`、mod依赖解析或 `custom_mods` 的运行时接入。现有 `MOD.md` 是内容素材，正文中“参见某 mod”仍只是文字。

可参考的现有代码：

| 位置 | 当前职责 | 对 mod 的参考意义 |
|---|---|---|
| `origin_agent/abstract/skills/frontmatter.py` | 解析 Markdown 的 YAML frontmatter 子集 | 可复用或抽取通用解析能力，但必须补足 mod 的严格格式检查 |
| `origin_agent/abstract/skills/loader.py` | 技能发现、读取、模板处理 | 参考目录与读取接口，不照搬宽松路径解析、内联命令执行或未知占位符置空行为 |
| `origin_agent/component/tools/skills.py` | `RecallSkill` 无名称列举、有名称返回全文 | 参考工具结果交付方式，而不是假设技能维护了永久正文加载状态 |
| `origin_agent/entry/agent_support/messages.py` | 技能简目录、系统提示词和 History 组装 | 放置 mod 入口说明的接入点之一 |
| `origin_agent/abstract/tools/tool.py` | 工具对象与调用级执行材料 | 新工具继续使用现有对象协议 |
| `origin_agent/system/prompt.py` | 业务提示词与会话功能模板组装 | 复用运行时值的权威来源，后续逐项移除重复全文注入 |

复用原则是复用解析、类型、路径和消息接口，不复制技能中不适合 mod 的历史兼容行为；也不为 mod 重新实现一套工具执行器、审批系统或 History。

## 3. mod、技能与工具集的分工

| 概念 | 承载内容 | 加载的效果 |
|---|---|---|
| mod | 系统功能的使用约定与指导 | 把文档正文作为工具结果带入上下文 |
| 技能 | 可复用任务知识、流程及配套资料 | 保持现有技能机制，不因 mod 接入而改变 |
| 工具集 | 注册工具的定义与可用成员 | 继续由 `LoadToolset` 等现有流程控制 |

mod 可以说明某个任务需要先加载某个工具集，但首版不会因为读到这些文字就自动调用 `LoadToolset`。`dependencies` 只引用 mod，不跨类型引用技能、工具集、文件路径或 Python 模块。

## 4. 文件布局与名称

拟使用项目根目录下的以下结构：

```text
custom_mods/
  DEV-README.md
  ExampleFeature/
    MOD.md
  ExampleShared/
    MOD.md
```

首版只发现直接子目录中的 `MOD.md`，不递归发现分类目录，不将根目录开发文档或占位文件视为 mod。

### 4.1 名称约定

- 目录名是唯一的规范名称，也是工具参数、依赖和关联的引用名称。
- 新名称采用 ASCII 字母开头，后接字母、数字、下划线或连字符，最长 64 字符。
- 可显式写 `name`，但必须与目录名完全相同；不提供显示名称、目录名称和别名三套身份。
- 在所有平台上检查不区分大小写的名称冲突，防止一组文件在 Linux 可区分、在 Windows 却指向同一个目录。
- 对外使用规范名称；大小写不匹配时返回建议名称，不自行选择另一个文件。
- 不接受绝对路径、逻辑路径、URL、`..`、斜杠或反斜杠作为 mod 名称。

### 4.2 读取边界

mod 根目录由项目根定位能力提供，不取决于调用工具时的当前工作目录，也不复制到 fast仓库或 slow仓库中。

缺少整个可选目录表示没有安装 mod。目录存在但读取失败、文档无法解码等不能伪装成空目录。

解析后必须确认目录及 `MOD.md` 没有通过符号链接、Windows junction 或其他 reparse point 越出固定根。首版不支持链接式安装。

后续如新增 `custom_mods:` 沙盒命名空间，应在 fast/fallback 模式下只读，并通过现有 Sandbox 的唯一映射与权限表接入。工具按名称加载，不依赖先暴露任意物理路径读取能力。当前尚无该命名空间，不应在现有提示词中宣称已经可用。

## 5. MOD.md 格式

新编写的 mod 推荐使用技能风格的 frontmatter：

```markdown
---
name: ExampleFeature
description: Explain how to use an example system feature.
dependencies:
  - ExampleShared
related:
  - ExampleAlternative
---

# Example Feature

Use this guidance when the task needs the example feature.
```

| 字段 | 类型与含义 |
|---|---|
| `name` | 可选字符串；出现时必须等于目录名 |
| `description` | 新格式必填的非空单行字符串；用于发现，不代替正文 |
| `dependencies` | 可选名称数组，缺省 `[]`；全部是必需依赖 |
| `related` | 可选名称数组，缺省 `[]`；全部是可选关联入口 |

正文必须非空。名称数组不接受单字符串、对象或路径，不自动做隐式类型转换。数组内重复名称保留首次出现的顺序并去重。

frontmatter 不支持任意对象构造、YAML 执行标签、文件 include 或表达式。出现未知字段、重复键、格式错误或字段类型错误时，应返回明确诊断，不能静默忽略或把后一个值覆盖前一个值。

现有技能解析器具有部分宽松行为。即使复用其底层解析代码，也必须提供满足上述要求的严格入口，并保持技能既有接口不被无意改变。

### 5.1 现有无 frontmatter 文档的兼容

首版允许完全没有 frontmatter 的现有 `MOD.md`：

- 名称使用目录名。
- 依赖与关联都视为 `[]`，不会根据正文猜测。
- 简介取正文中首条非空、非标题、非独立占位符的说明，按简介上限展示；找不到时明确显示缺少简介。
- 列举结果标明该文件尚无结构化元数据，建议开发者补齐。

只有“完全没有 frontmatter”适用这条兼容规则。已经写入 frontmatter 但格式错误的文档不能降级成普通正文继续加载。

### 5.2 正文引用不自动形成依赖

`See ExampleShared mod`、普通 Markdown 链接、示例代码中的名称，均不触发自动加载。

必须自动一起加载的内容写入 `dependencies`；仅作为延伸阅读或替代方案的内容写入 `related`。文件内的两者应与正文说明保持一致。

## 6. 依赖与关联语义

### 6.1 必需依赖

`A.dependencies = [B, C]` 表示加载 A 必须同时取得 B、C 及其递归依赖。

- 依赖在使用者之前输出。
- 相同依赖在本次批量调用中只输出一次。
- 任何必需依赖缺失、无效、不可读取、超预算或无法渲染，整个调用失败。
- 禁止直接自依赖和间接循环；错误必须携带完整循环链。
- 不因缺少依赖而自动创建文件、下载内容、调用技能或启动子Agent。

### 6.2 可选关联

`A.related = [D]` 只表示读者可能还需要了解 D。

- 返回 D 的名称、简介与可用状态，不返回 D 的正文，也不遍历 D 的依赖。
- Agent 决定需要阅读 D 后，可将它与其他目标放进下一次批量调用。
- A 与 D 可以互相关联；关联环不构成依赖错误。
- 关联目标不存在时返回可见诊断，不因此拒绝一个本来完整的必需依赖集合。
- 已在本次依赖结果中的目标不重复输出为待阅读建议。

这一区分用于避免“每份指导都提及其他指导”最终变成全量加载。

## 7. 一次调用的递归解析

拟采用按声明顺序执行的深度优先后序遍历，或具有相同稳定结果的迭代实现。

1. 校验输入名称数组，按输入顺序去重。
2. 为本次调用建立名称索引和文档读取材料，不复用其他调用的可变遍历状态。
3. 访问每个请求目标：标记为正在访问，按数组顺序访问其 `dependencies`。
4. 再次访问正在访问的名称时，立即报告循环及当前依赖链。
5. 依赖全部完成后，将该 mod 加入结果；已完成名称直接复用本次材料。
6. 所有目标解析完成后，用同一份运行时值快照渲染各份正文，检查总结果预算。
7. 收集并去重可选关联信息，完成最终结果；任一步失败都不交付部分正文。

例如，独立教学依赖关系为：

```text
ExampleSummary -> [ExampleStorage, ExampleTheme]
ExampleTheme   -> [ExampleStorage]
ExampleExtra   -> [ExampleStorage]
```

一次请求 `[ExampleSummary, ExampleExtra]` 的结果顺序为：

```text
ExampleStorage, ExampleTheme, ExampleSummary, ExampleExtra
```

只产生一次外部工具调用和一个配对工具结果，公共依赖正文只出现一次。递归过程不调用 LLM，也不在程序内部循环分发 `RecallMod` 工具。

## 8. 拟议工具接口：RecallMod

选择与 `RecallSkill` 相近的名称和交互，但支持名称数组。首版不同时提供功能重叠的 `LoadMod`、`ListMods` 和单名称别名参数。

### 8.1 参数

```json
{
  "names": ["ExampleSummary", "ExampleExtra"]
}
```

- 省略 `names`：返回 mod 简目录与诊断。
- 提供 `names`：必须是非空字符串数组，一次批量加载全部目标与依赖。
- `names: []`、`null`、错误类型或空名称均明确拒绝，不将其当成列举分支。
- 不接受调用方指定物理根目录、资源归属会话、任意模板变量或依赖搜索目录。

### 8.2 列举结果

列举只返回名称、简介、直接依赖、直接关联和元数据状态等发现信息，不返回正文，也不递归展开依赖图。无效条目以诊断展示，不能宣称为正常可加载条目。

同名冲突不能采用“扫描到的第一个获胜”。涉及冲突的名称必须不可加载，并明确展示冲突原因。

### 8.3 加载结果

拟议成功结果形态：

```json
{
  "success": true,
  "requested": ["ExampleFeature"],
  "order": ["ExampleShared", "ExampleFeature"],
  "mods": [
    {
      "name": "ExampleShared",
      "description": "Shared example guidance.",
      "dependencies": [],
      "content": "The rendered shared guidance.",
      "content_version": "sha256-of-source-bytes"
    },
    {
      "name": "ExampleFeature",
      "description": "Example feature guidance.",
      "dependencies": ["ExampleShared"],
      "content": "The rendered feature guidance.",
      "content_version": "sha256-of-source-bytes"
    }
  ],
  "related": [],
  "warnings": []
}
```

`mods` 数组就是依赖有序的全文结果。不要额外再返回一份拼接后的相同正文或 `raw_content`，以免重复占用上下文。

`content_version` 标识读到的原始文件字节，不代表渲染内容永远不变。同一文件在不同会话或模型配置下可以渲染出不同文本。

失败返回稳定的 `code`、简洁 `error`、失败名称和依赖链；不携带已经读取的部分正文，也不设置“已加载”标志。

### 8.4 工具执行约定

- 按现有对象协议声明为 `BaseTool`，通过顶层 `TOOLSET` 加入 `core`。
- 首版拟使用 `safe` 和 `EVERY`，仅允许读取可信 mod 文档；工具可见性仍接受实际 Loop 的过滤。
- 磁盘读取与解析使用同步工具，由现有 ToolRegistry 线程池执行，避免阻塞事件循环。
- `handle` 只准备一次调用的结果；不修改应用、文件或会话加载集合，不需要专属 `after_handle` 副作用。
- 返回结果通过所属 Loop 已有的提交、配对与前端回显路径处理，不绕过 History 保存。
- 读取权限不意味着可以实际使用文档介绍的工具；尤其不扩大临时Agent的 `TASKAGENT ∩ safe` 授权交集。

## 9. 正文进入上下文的位置与生命周期

### 9.1 首版使用工具结果，不重复注入系统正文

与现有技能加载相近，渲染后的正文随一个工具结果进入 History，再由既有消息组装进入后续模型请求。

首版不同时将同一正文追加为 system message、钩子块或额外 user message，不维护一份全局“所有会话已加载 mod 正文”。

“加载到上下文”表示成功提交的结果会出现在后续模型请求中，不表示当前已经发出的请求能够被修改。

### 9.2 系统提示词的最小入口

默认仅保留：

- mod 系统存在，以及它用于系统功能指导。
- `RecallMod` 无 `names` 列举、有 `names` 批量加载。
- 必需依赖会自动递归加载，关联不会自动加载。
- 仅根据当前工具定义和权限执行实际操作。

默认不放全部 mod 正文、完整依赖图或全部功能说明。首版也不默认复制一份完整简目录到系统提示词和工具描述两处；先通过列举发现，已知名称可直接加载。

若未来选择像技能一样常驻名称与简介的轻目录，应作为明确的呈现策略变更，只放发现信息，不改变正文按需加载和权限语义。

### 9.3 去重范围与重复调用

首版保证的是**同一次调用内去重**，不是跨所有历史轮次永久去重。

- Agent 已知多项需求时应一次传入多个名称，避免分次请求同一个公共依赖。
- 再次明确请求同名 mod 时，重新读取并完整返回本次依赖集合；不根据一个旧名称集合返回空正文。
- 不声称“曾经加载过”就代表正文现在仍在模型上下文内。
- 首版不按历史正文猜测是否加载，也不新增持久化的 `loaded_mods` 文件。

跨调用的智能去重、正文卸载或活跃 mod 保持机制如需增加，应独立定义内容版本、请求可见性、压缩及会话迁移契约，不能借用工具集加载状态直接实现。

### 9.4 压缩、旋转、分支和重新生成

mod 工具结果遵循现有 History 规则：压缩可能将其变成摘要，消息删除或重新生成可能移除它，旋转/分支/合并只继承各自既有的历史范围。

因此不保证 mod 正文在这些操作后仍然存在。需要原始指导或新的会话路径时，显式重新加载；不要从摘要恢复精确占位符值或假定旧资源目录就是新会话目录。

重新生成不会执行一种独立的 mod 状态回滚，因为首版不存在额外的已加载状态存储。旧工具结果已经提交时，也不自动重放其业务操作。

### 9.5 多Agent、子Agent与临时Agent

- 普通主会话和随意聊聊会话：结果进入本会话的 History。
- 多Agent模式：结果进入共享 History，但实际可见性仍由现有消息机制决定，不能据此宣称每个参与者必然读到全文。
- 普通子Agent：结果进入自己的 History，父Agent仅收到既有反馈，不自动继承其全部 mod 正文。
- 临时Agent：可以在安全授权范围内通过工具读取指导；仍无系统提示词、无历史持久化，父Agent不能假设它继承了主会话已读 mod。

mod 的元数据和正文不能自行修改上述可见性或持久化规则。

## 10. 运行时占位符

mod 是功能指导模板，运行时值由可信代码提供，不由模型参数覆盖。

### 10.1 值的来源

拟复用或抽取现有业务模板组装中的显式值来源，形成调用级只读渲染材料。公共值包括以下类型：

| 值 | 权威来源与约定 |
|---|---|
| `session_id` | 资源归属主会话 ID，使用 `ToolContext.resource_session_id`；普通子Agent/临时Agent不能错误使用自身子会话 ID |
| `owner_intro` | 由实际调用身份生成的归属说明，不由 mod 声称自己属于某个父会话 |
| `soul_file` | 当前调用可取得的活动 Profile 的 SOUL 选择；按现有正式组装规则处理缺省，不从 mod 名称或文本推断 |
| `gateway_port`、`mcp_config_path` | RuntimeContext 与现有路径转换能力提供的配置值 |
| `files_prefix`、`downloads_prefix`、`local_font_prefix` | 已有协议常量 |
| `variables_dir` | 已有会话变量目录常量，不通过读取变量文件推导 |
| `fix_fork_path`、`fix_log_path` | fallback 模式下真实修复目标和错误日志配置；其他模式中不能捏造有效值 |

`session_id` 在这里沿用现有会话功能模板的资源归属口径，不等于所有语境中的当前执行会话 ID。工具内部用于保存结果、审批与反馈的真实 `context.session_id` 不得被它覆盖。

普通子Agent不一定持有主会话相同的活动 Profile。渲染代码必须按公开接口确定是否有值，不能跨类反射获取私有字段，或偷用父Agent的配置冒充当前执行模型。

### 10.2 替换规则

- 支持显式登记的简单 `{{key}}` 或 `{{ key }}`。
- 只替换一次；替换值中即使包含相同语法，也不二次展开。
- 不执行表达式、属性访问、函数、Shell、Python 或环境变量插值。
- 需要展示字面模板语法时，使用转义形式 `\{{key}}`，输出时保留为字面内容。
- 未登记的占位符，以及正文用到但在当前调用中不可用的必要值，都使该批返回明确错误；不静默置空。
- 不渲染 frontmatter 的名称、依赖或关联，避免运行时改变依赖图。
- 不把 API Key、访问令牌或任意运行时对象字典作为通用模板变量暴露。

渲染材料在一次调用中固定，各依赖使用同一组值；之后 Profile 或会话发生变化，不改写已经提交的历史工具结果。需要最新值时重新加载。

新增公共占位符必须集中定义来源和可用条件；不能让任意 mod 通过自定义 Python 模块注册读取系统秘密的解析器。

## 11. 失败、预算与文件变化

### 11.1 全有或全无交付

一次批量请求的任何必需目标失败，均不交付部分正文。这里的完整性是结果交付完整性，不是跨文件磁盘事务，也不是对既有 History 的回滚承诺。

拟议错误分类至少包括：

| code | 情况 |
|---|---|
| `invalid_argument` | 参数类型、空数组或名称格式错误 |
| `unknown_mod` | 请求目标不存在 |
| `invalid_metadata` | frontmatter 格式或字段不合法 |
| `duplicate_name` | 存在大小写等价的名称冲突 |
| `missing_dependency` | 必需依赖不存在，附完整来源链 |
| `dependency_cycle` | 直接或间接循环，附循环路径 |
| `unreadable_mod` | 权限、解码、文件类型或读取失败 |
| `unsafe_path` | 路径越界、链接或 reparse point |
| `missing_template_value` | 当前调用无法提供正文需要的值 |
| `unsupported_placeholder` | 未登记或不支持的模板语法 |
| `budget_exceeded` | 文件、深度、数量或输出预算超限 |
| `source_changed` | 读取期间检测到相关文档变化 |

这些是已识别的输入/资源问题，应明确返回；未知内部错误继续按项目快速失败约定传播，不通过宽泛捕获转为空文档或成功。

### 11.2 首版建议预算

以下数值是本稿建议的有限初始预算，不是当前已有常量：

| 项目 | 建议值 |
|---|---|
| 目录可发现 mod 数量 | 512 |
| 单次请求目标数量 | 32 |
| 单次依赖集合大小 | 32 |
| 最大依赖链深度 | 16，目标本身计第 1 层 |
| 单文件大小 | 64 KiB，按原始 UTF-8 字节计 |
| frontmatter 大小 | 8 KiB，包含在单文件额度内 |
| 简介长度 | 256 Unicode 码点 |
| 单 mod 的依赖/关联数组长度 | 分别 32 |
| 单次读取文件原始字节总量 | 256 KiB |
| 编码后的完整工具结果大小 | 512 KiB |

实现时集中放入对应职责的 `entity/constant/` 模块并显式导出，不在解析函数中散落数值。目录、数组和文件读入也必须有限，不能先无限读取再做输出截断。

模板替换后的内容以及 JSON 编码开销都计入结果额度。超限拒绝，不截断依赖正文后宣称加载成功。接入时还必须核对工具注册表、通用工具结果与模型请求预算，确保它们不会在成功返回后静默截断文档；无法完整交付时明确失败。

### 11.3 一致性与缓存

首版不要求常驻缓存或文件 watcher。同一次调用中，同名文件只建立一份读取材料，并从同一份原文同时解析元数据与正文，不分别读出两个版本。

读取前后及返回前复核文件身份/版本，检测到变化就拒绝该批。不承诺跨多个文件取得同一时刻的原子快照，也不依靠只比较文件名证明内容未变。

目录列举只做有限元数据读取，不进行脚本执行、依赖下载或环境安装检查。未来如增加缓存，只能缓存带版本的原始内容或索引；不能将某会话渲染后的路径和 Profile 值作为跨会话缓存复用。

## 12. 架构分层与代码接入方向

以下是建议职责，不代表已经创建这些文件或增加 System：

| 位置 | 建议职责 |
|---|---|
| `abstract/mods/` | 有界发现、严格元数据解析、名称解析、依赖遍历与读取；输入显式目录，不查询 Application |
| `entity/puretype/` | 不依赖正式消息类的元数据、结果和诊断模型，通过所属包显式再导出 |
| `entity/constant/` | mod 文件名、预算、名称规则和通用协议常量 |
| `system/prompt.py` 或按职责拆分的业务组装模块 | 当前调用的可信模板值与最小系统入口说明；不拥有另一份 mod 存储 |
| `component/tools/` | `RecallModTool` 与 `TOOLSET`，通过公开 ToolContext 取得上下文，适配原有工具结果 |
| `system/sandbox.py` 与命名空间常量 | 后续选择暴露 `custom_mods:` 时的唯一只读路径映射 |

复用通用 Markdown/frontmatter 能力时保持依赖方向明确，不让抽象加载器反向依赖具体 Loop、System 或功能 mod。

首版无需为了读取文档新增一个 AsyncSystem。纯函数与调用级读取材料足够时不建立长期服务；确需跨调用缓存时，由 Application 直接或间接持有唯一对象，不使用模块级可变单例。

纯数据类与带校验/转换方法的业务模型按项目现有规范分开放置。结果进入现有 ToolResultMessage，不新增专属消息角色，也不为了 mod 自行维护第二份 History。首版不新增持久化数据文件；如后续选择持久化状态，须另行确定 easysave 版本及缺失/迁移策略。

## 13. 迁移边界

建议按以下顺序推进，后续源码实施仍需单独授权：

1. 完成通用格式与加载接口，实现批量依赖解析和受控渲染。
2. 在相关 Agent 请求路径中提供最小发现入口，确认工具结果可完整进入上下文。
3. 为已有无 frontmatter 文档补齐简介、依赖和关联；修订已知与开发文档或源码不一致的功能说明。
4. 明确每一块指导的使用条件，以及普通模式、随意聊聊、多Agent模式和子会话的覆盖范围。
5. 逐块移除原提示词中的重复功能全文，保留功能事实的权威运行时来源和必要的基础约束。
6. 同步根开发文档、术语表、受影响子包文档以及涉及的新字段归属/公开接口记录。

不能仅删除 `base.txt` 的一处段落就认定迁移完成。现有功能提示词也可能由主会话、子会话或多Agent启动路径单独追加，必须逐一核对。

模式运行所必需的路由格式、角色身份、工具安全边界、拒绝/中断规则等仍需在相应运行路径中可靠可用，不可全部藏进可选 mod。加载 mod 也不能改变主Agent角色名的真实读取来源，或把人格正文与身份元数据混为一谈。

本稿编写期间不修改已有 `MOD.md`、原提示词模板或运行源码，不代表上一轮内容审阅列出的差异已经修复。

## 14. 后续验收要点

以下是未来实施后的验收要求，本轮未执行任何校验或应用：

- 无参数列举、已知名称直接加载、多个目标一次加载均有明确结果。
- 链式依赖、菱形依赖和重复目标按稳定顺序完整返回，公共正文只出现一次。
- 自依赖、间接循环、缺失依赖均失败，并能定位完整路径。
- 关联可互相引用但不自动加载；关联缺失可诊断，不破坏必需依赖结果。
- 无 frontmatter 文档能按兼容规则读取；损坏 frontmatter、重复键、错误类型和大小写冲突不能静默通过。
- 目录不存在可正常表达为空；权限失败、链接越界、并发修改和预算超限不会伪装为空或部分成功。
- 子Agent与临时Agent拿到父主会话的资源路径，但结果仍写入自己的 History，审批与工具权限不扩大。
- 同名 mod 的占位符随调用身份和 Profile 正确渲染，不跨会话串用值，也不二次执行模板内容。
- 普通工具结果、压缩后的工具链、重新生成、会话旋转和子会话停止均保持既有配对与持久化规则。
- 临时Agent仍无系统提示词；mod 通过工具结果进入其临时上下文，而非新增隐藏系统正文。
- 原功能全文移出后，系统入口仍能指导发现与加载；同一正文没有被工具结果与系统提示词重复注入。
- 实际工具调用次数能够说明收益：一次加载得到目标及其全部依赖，而不是模型逐层发起工具调用。

## 15. 本稿设计取舍

为避免把未讨论的复杂机制隐含进实现，本稿明确采用以下首版取舍：

- 正文走现有工具结果，默认系统提示词只保留加载入口。
- `dependencies` 是必需递归加载，`related` 是不自动加载的关联入口。
- 一次调用批量请求、调用内去重、失败不交付部分正文。
- 不维护永久已加载集合，不承诺跨压缩保留正文或跨调用自动去重。
- 不自动加载工具集，不执行 mod 中的脚本，不新增持久化状态。

如果后续希望改变其中任意一项，应先修订本设计并确认消息、权限和生命周期影响，再实施代码；不能把这些取舍误写成当前系统已经具备的能力。
